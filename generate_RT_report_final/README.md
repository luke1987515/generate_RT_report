# Generate RT Report - 統一報告生成工具

## 概述

這是 Luke 和 Piero 協作開發的**統一報告生成工具**，用於自動化測試報告的生成流程。

基於 Luke 和 Piero 的多個版本整合而成，提取了 **auto_report_v33_claude** 的完整功能集。

### 主要特性
- ✅ 從 Excel 讀取測試數據
- ✅ 自動填充 Word 報告模板  
- ✅ 清理廢棄測項的相關章節
- ✅ 清理空標題和孤立段落
- ✅ 自動更新報告 TOC (目錄)
- ✅ 詳細的日誌記錄和錯誤報告

### 開發團隊
- **Luke**: 主要架構和整合  
- **Piero**: 可靠度測試和功能驗證

### 版本信息
- **當前版本**: v1.0
- **基於**: auto_report_v33_claude (含完整功能集)
- **最後更新**: 2024

## 使用方式

### 第 1 步: 準備 Excel 檔案 (`Master_Log.xlsx`)

**欄位要求：**

| 欄位名稱 | 類型 | 說明 |
|---------|------|------|
| 測項名稱 | 文字 | 測試項目名稱 |
| 測試狀態 | 文字 | 狀態值: "通過"、"失敗"、"跳過" |
| 開始時間 | 文字 | 開始時間 (如: 2024-01-15 09:30) |
| 結束時間 | 文字 | 結束時間 (如: 2024-01-15 10:15) |
| Physical Damage | 文字 | 物理損傷檢查結果 |
| Functional Check | 文字 | 功能檢查結果 |

**範例數據：**

```
測項名稱                 | 測試狀態 | 開始時間          | 結束時間          | Physical Damage | Functional Check
PC-001 基本功能測試       | 通過    | 2024-01-15 09:30 | 2024-01-15 10:15 | 無損傷         | 正常
PC-002 壓力測試          | 跳過    | -               | -               | -             | -
PC-003 環境適應性測試     | 通過    | 2024-01-15 11:00 | 2024-01-15 11:45 | 無損傷         | 正常
```

**重要提示:**
- 第一行為欄位標題（必須）
- 測試狀態為 "跳過" 的項目，其對應的報告章節會被自動刪除
- 所有必要欄位都要有，即使為空

### 第 2 步: 準備 Word 模板 (`Template.doc`)

**必要內容：**

1. **佔位符**（會被自動替換）
   - `{Report_Title}` - 報告標題
   - `{Report_Date}` - 報告日期
   - `{Author}` - 作者
   - （可自行添加其他佔位符）

2. **表格**
   - **3.1 Test Item Result** - 測項結果表
     - 用於填充: 測項名稱、開始時間、結束時間、狀態
   - **4.x 詳細結果表** - 含 "Physical Damage" 或 "Functional Check" 字樣
     - 用於填充: 詳細測試結果

3. **目錄 (TOC)**
   - 如果報告包含 Word TOC，工具會自動更新

**模板範例結構:**
```
報告標題: {Report_Title}
報告日期: {Report_Date}
作者: {Author}

[第1章 概述]
...

[第3章 測試結果]
3.1 Test Item Result
[表格: 測項 | 開始時間 | 結束時間 | 狀態]

[第4章 詳細結果]
4.1 Physical Damage
[表格: 項目 | Physical Damage 結果]

4.2 Functional Check
[表格: 項目 | Functional Check 結果]
```

### 第 3 步: 運行工具

在存放 `main.py`、`Master_Log.xlsx`、`Template.doc` 的資料夾中運行：

```bash
python main.py
```

### 第 4 步: 查看輸出

- **輸出報告**: `Final_Report.docx`
- **運行日誌**: `report_generation.log`

## 處理流程

工具按以下 **7 個階段** 處理：

### 階段 1: 驗證輸入檔案
- 檢查 `Master_Log.xlsx` 是否存在
- 檢查 `Template.doc` 是否存在
- 確保所有必要的 Excel 欄位存在

### 階段 2: 讀取 Excel 數據
- 讀取 Excel 中的所有測試項目
- 驗證欄位名稱
- 提取報告訊息

### 階段 3: 替換文本佔位符
- 在主文本中替換 `{Report_Title}`、`{Report_Date}` 等
- 在表格中進行替換
- 在標題和頁腳中進行替換

### 階段 4: 填充表格數據
- 填充 3.1 Test Item Result 表格（測項名稱、時間、狀態）
- 填充 4.x 詳細結果表格（Physical Damage / Functional Check）
- 自動編號更新

### 階段 5: 刪除跳過的章節
- 偵測測試狀態為 "跳過" 的測項
- 刪除對應的報告章節

### 階段 6: 清理空標題
- 第 1 掃描: 刪除空標題
- 第 2 掃描: 刪除連續空段落
- 第 3 掃描: 檢查標題後的元素（預留擴展）

### 階段 7: 更新 TOC
- 使用 Word COM 介面更新目錄
- 確保報告結構的一致性

## 故障排查

### 問題 1: 「Excel 檔案不存在」

**原因**: 找不到 `Master_Log.xlsx`

**解決方案**:
1. 確保 `Master_Log.xlsx` 在同一資料夾
2. 檢查檔名拼寫 (區分大小寫)
3. 確保檔案不被其他程式鎖定

### 問題 2: 「Word 模板檔案不存在」

**原因**: 找不到 `Template.doc`

**解決方案**:
1. 確保 `Template.doc` 在同一資料夾
2. 檢查副檔名 (應為 `.doc` 或 `.docx`)
3. 確保檔案不被 Word 程式開啟

### 問題 3: 「Excel 缺少必要欄位」

**原因**: Excel 中缺少必要的欄位

**解決方案**:
1. 檢查 Excel 第一行的欄位名稱
2. 確保包含: '測項名稱', '測試狀態', '開始時間', '結束時間', 'Physical Damage', 'Functional Check'
3. 注意繁體中文的拼寫

### 問題 4: 「更新 TOC 失敗」

**原因**: Word 未安裝或 COM 介面出錯

**解決方案**:
1. 確保安裝了 Microsoft Word
2. 確保 Word 不在運行中
3. 重新安裝 pywin32: `pip install --upgrade pywin32`
4. 可以忽略此警告，報告仍會生成

### 問題 5: 表格無法正確填充

**原因**: 模板中的表格結構不符合預期

**解決方案**:
1. 檢查 3.1 表格是否包含 "Test Item Result" 標題
2. 確保表格至少有 4 列（測項、開始時間、結束時間、狀態）
3. 在 `main.py` 中調整表格識別邏輯
